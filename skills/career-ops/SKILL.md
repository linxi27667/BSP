# Career-Ops — AI 求职指挥中心

> "公司用 AI 筛候选人，我用 AI 选公司。"

## 数据路径

- **简历**：`career-data/cv.md`（用户创建）
- **评估报告**：`career-data/reports/`
- **追踪表**：`career-data/tracker.md`
- **求职信**：`career-data/cover-letters/`
- **公司档案**：`career-data/companies/`

## 意图路由

| 用户意图 | 操作 |
|---------|------|
| 粘贴 JD 或职位 URL | → **全自动流水线**（评估 + 报告 + 追踪） |
| "评估" / "evaluate" + JD | → **JD 评估**（A-F 评分，10 维度） |
| "简历" / "CV" / "pdf" | → **简历生成**（ATS 优化，关键词注入） |
| "求职信" / "cover" | → **求职信生成**（交互式，4 角度选择） |
| "追踪" / "tracker" / "状态" | → **查看申请看板** |
| "调研" / "deep" + 公司名 | → **深度公司调研** |
| "薪资" / "negotiate" | → **薪资谈判脚本** |
| "面试" / "interview" | → **面试准备（STAR 故事库）** |
| "批量" / "batch" + 多个 JD | → **批量并行评估** |

## 1. JD 评估（核心）

对职位进行 A-F 评分，10 个维度，6 个评估块：

### 评估维度

| 块 | 维度 | 权重 | 说明 |
|----|------|------|------|
| A | 角色匹配度 | 25% | 技能栈 vs JD 要求的匹配程度 |
| B | 简历契合度 | 20% | 经历 vs 职责的重叠度 |
| C | 级别策略 | 15% | 职级是否合理（过高/过低/匹配） |
| D | 薪资调研 | 15% | 市场薪资范围 + 地域调整 |
| E | 个性化空间 | 15% | 简历/求职信的定制空间 |
| F | 面试准备 | 10% | 可复用的 STAR 故事数量 |

### 评分标准

| 等级 | 分数 | 含义 |
|------|------|------|
| A | 4.5-5.0 | 强烈推荐，立即投递 |
| B | 3.5-4.4 | 值得投递，需针对性准备 |
| C | 2.5-3.4 | 可选，需要弥补差距 |
| D | 1.5-2.4 | 不推荐，差距较大 |
| F | <1.5 | 放弃 |

### Block G：真实性检查

额外检查项（不计入总分，但可一票否决）：
- 是否是虚假招聘（长期挂着的岗位）
- 是否是竞业限制公司
- 是否有明显的红旗（高流动率、差评多）

### 输出格式

```markdown
# JD 评估报告 - {公司名} - {职位名}

## 总评
- **评分**: {X.X}/5.0 ({等级})
- **推荐**: {立即投递 / 值得投递 / 可选 / 不推荐 / 放弃}
- **一句话**: {最关键的判断理由}

## 评分明细
| 块 | 维度 | 分数 | 说明 |
|----|------|------|------|
| A | 角色匹配 | {X}/5 | {说明} |
...

## 差距分析
- {差距1}: {具体描述} → {弥补建议}
- {差距2}: ...

## 定制建议
- 简历应突出：{...}
- 求职信角度：{...}
- 面试准备重点：{...}

## STAR 故事候选
- {经历1} 可用于回答 {问题类型}
- {经历2} ...

## Block G 真实性
- {检查结果}
```

## 2. 简历生成

ATS（Applicant Tracking System）优化简历：

```
1. 读取用户的基础简历（career-data/cv.md）
2. 分析 JD 关键词
3. 调整简历顺序，将最匹配的经历置顶
4. 注入 JD 关键词到工作经历描述中
5. 生成 ATS 友好的纯文本格式
```

**规则**：
- 不编造经历，只优化表述
- 保持量化数据（数字、百分比）
- 关键词自然融入，不堆砌
- 每段经历用 STAR 结构

## 3. 求职信生成

交互式流程，提供 4 个角度选择：

| 角度 | 适合场景 |
|------|---------|
| 技术热情 | 对公司技术栈有深入了解 |
| 行业洞察 | 对行业趋势有独特见解 |
| 文化契合 | 与公司价值观高度匹配 |
| 成长故事 | 展示快速学习和成长能力 |

**流程**：
```
1. 展示 4 个角度选项
2. 用户选择后，生成初稿
3. 用户审核，提出修改意见
4. 生成最终版本
```

## 4. 申请追踪

在 `career-data/tracker.md` 中维护 Markdown 表格：

```markdown
# 求职追踪

| 公司 | 职位 | 评分 | 状态 | 投递日期 | 最新进展 |
|------|------|------|------|---------|---------|
| {公司} | {职位} | {X.X} | {状态} | {日期} | {进展} |
```

**状态流转**：
```
待评估 → 已评估 → 已投递 → 笔试 → 一面 → 二面 → HR面 → Offer → 已拒绝/已接受
```

## 5. 深度公司调研

```
1. WebSearch 搜索公司基本信息
2. 搜索最新新闻和融资情况
3. 搜索员工评价（Glassdoor/脉脉等）
4. 搜索技术栈和开源项目
5. 整合为公司档案
```

**输出**：保存到 `career-data/companies/{公司名}.md`

## 6. 薪资谈判脚本

```
1. 评估用户当前薪资和期望
2. 调研目标公司/地区的市场薪资
3. 生成谈判话术（含地域折扣反驳策略）
4. 准备竞争 offer 的杠杆策略
```

## 7. 面试准备（STAR 故事库）

维护一个可复用的 STAR 故事库：

```markdown
# STAR 故事库

## 故事1: {标题}
- **Situation**: {背景}
- **Task**: {任务}
- **Action**: {行动}
- **Result**: {结果}
- **可用于**: {面试问题类型}

## 故事2: ...
```

积累 5-10 个万能故事，覆盖：技术难题、团队冲突、领导力、失败教训、创新突破。

## 执行规则

1. **先读简历**：任何操作前先确认 `career-data/cv.md` 存在
2. **不编造**：简历/求职信中不虚构经历
3. **量化优先**：所有描述尽量用数字说话
4. **ATS 友好**：避免花哨格式，关键词密度合理
5. **追踪一切**：每次评估都更新 tracker
6. **渐进优化**：随着交互增多，评估越来越精准

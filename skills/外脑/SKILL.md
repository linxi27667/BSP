# Karpathy 外脑 — LLM Wiki 知识管理

基于 [Karpathy 的 LLM Wiki 模式](https://x.com/karpathy)，将笔记库变成可查询的知识图谱。

**核心理念**：知识像复利一样累积。每次摄取都让知识库更丰富。

## 笔记库路径

用户的 Obsidian 笔记库位于：
- **主库**：`C:\Users\30817\Documents\Obsidian Vault\`
- **AI 工作日志**：`C:\Users\30817\Documents\Obsidian Vault\笔记\ai工作日志记忆\`

## 意图路由

| 用户意图 | 操作 |
|---------|------|
| "外脑" / "总结笔记" / "整理知识" | → 执行 **知识盘点**（扫描笔记库，生成结构化摘要） |
| "摄取" / "ingest" + 文件/URL | → 执行 **知识摄取**（读取源文件，提取实体，创建 wiki 页面） |
| 查询某个主题 | → 执行 **知识查询**（热缓存 → 索引 → 具体页面，带引用回答） |
| "lint" / "健康检查" | → 执行 **知识库体检**（孤立页、死链、过期内容） |
| "autoresearch" + 主题 | → 执行 **自主调研**（3 轮网络搜索 + 差距填补） |

## 1. 知识盘点（默认模式）

当用户说"外脑"或"总结我们的笔记"时，执行以下流程：

```
1. 扫描 Obsidian Vault 目录结构
2. 按主题分类笔记（技术/项目/学习/工作日志）
3. 识别核心实体（技术栈、项目名、关键概念）
4. 生成结构化知识地图（Markdown 格式）
5. 保存到 Obsidian Vault 的 wiki 子目录
```

**输出格式**：
```markdown
# 知识地图 - {日期}

## 核心领域
### {领域1}
- 关键概念：...
- 相关笔记：[[笔记A]], [[笔记B]]
- 知识缺口：...

### {领域2}
...

## 最近活跃
- {笔记1} - {最后修改时间}
- {笔记2} - {最后修改时间}

## 知识缺口（待补充）
- {缺口1}
- {缺口2}
```

## 2. 知识摄取

读取源文件，提取实体和概念，创建交叉引用：

```
1. 读取源文件内容
2. 提取关键实体（人名、技术、项目、概念）
3. 为每个重要实体创建/更新 wiki 页面
4. 建立双向链接（[[实体A]] ↔ [[实体B]]）
5. 更新索引文件
```

**Wiki 页面模板**：
```markdown
# {实体名}

## 概要
{一段话总结}

## 关联实体
- [[实体A]] - {关系描述}
- [[实体B]] - {关系描述}

## 来源
- {源文件路径}

## 更新日志
- {日期}: {变更}
```

## 3. 知识查询

三层查询架构，最小化 token 消耗：

```
第1层：hot.md 热缓存（~500词，最近上下文）
  ↓ 未命中
第2层：wiki-index.md 索引（所有页面的一行摘要）
  ↓ 定位到具体页面
第3层：具体 wiki 页面（详细内容）
```

**回答格式**：始终带引用，指向具体 wiki 页面。

## 4. 知识库体检

检查项目：
- 孤立页面（无任何链接指向）
- 死链（指向不存在的页面）
- 过期内容（超过 90 天未更新的技术笔记）
- 缺失交叉引用（相关笔记之间没有链接）
- 空页面（只有标题没有内容）

## 5. 自主调研

```
1. 确定主题和知识缺口
2. 第1轮：WebSearch 搜索基础信息
3. 第2轮：搜索最新进展和争议
4. 第3轮：搜索实践案例和最佳实践
5. 综合整理，创建/更新 wiki 页面
6. 标记新增知识和仍存在的缺口
```

## 组织模式

支持四种笔记组织哲学，可在对话中切换：

| 模式 | 风格 | 适合场景 |
|------|------|---------|
| **Generic** | 默认，无偏好 | 通用 |
| **LYT** | MOC（Map of Content）导航 | 大型知识库 |
| **PARA** | 按可操作性分文件夹 | 项目驱动 |
| **Zettelkasten** | 原子化时间戳笔记 | 深度思考 |

## 执行规则

1. **先扫描再行动**：始终先了解笔记库当前状态
2. **保留原有结构**：不破坏用户已有的笔记组织
3. **双向链接**：每次创建页面都要建立 `[[双向链接]]`
4. **带引用回答**：查询结果必须指向具体笔记路径
5. **增量更新**：不重复创建已存在的页面，只更新差异
6. **热缓存维护**：每次交互后更新 hot.md（最近 500 词上下文）

## 1. 知识盘点（默认模式）

当用户说"外脑"或"总结我们的笔记"时，执行以下流程：

```
1. 扫描 Obsidian Vault 目录结构
2. 按主题分类笔记（技术/项目/学习/工作日志）
3. 识别核心实体（技术栈、项目名、关键概念）
4. 生成结构化知识地图（Markdown 格式）
5. 保存到 Obsidian Vault 的对应目录
```

**输出格式**：
```markdown
# 知识地图 - {日期}

## 核心领域
### {领域1}
- 关键概念：...
- 相关笔记：[[笔记A]], [[笔记B]]
- 知识缺口：...

### {领域2}
...

## 最近活跃
- {笔记1} - {最后修改时间}
- {笔记2} - {最后修改时间}

## 知识缺口（待补充）
- {缺口1}
- {缺口2}
```

## 2. 知识摄取

读取源文件，提取实体和概念，创建交叉引用：

```
1. 读取源文件内容
2. 提取关键实体（人名、技术、项目、概念）
3. 为每个重要实体创建/更新 wiki 页面
4. 建立双向链接（[[实体A]] ↔ [[实体B]]）
5. 更新索引文件
```

**Wiki 页面模板**：
```markdown
# {实体名}

## 概要
{一段话总结}

## 关联实体
- [[实体A]] - {关系描述}
- [[实体B]] - {关系描述}

## 来源
- {源文件路径}

## 更新日志
- {日期}: {变更}
```

## 3. 知识查询

三层查询架构，最小化 token 消耗：

```
第1层：hot.md 热缓存（~500词，最近上下文）
  ↓ 未命中
第2层：wiki-index.md 索引（所有页面的一行摘要）
  ↓ 定位到具体页面
第3层：具体 wiki 页面（详细内容）
```

**回答格式**：始终带引用，指向具体 wiki 页面。

## 4. 知识库体检

检查项目：
- 孤立页面（无任何链接指向）
- 死链（指向不存在的页面）
- 过期内容（超过 90 天未更新的技术笔记）
- 缺失交叉引用（相关笔记之间没有链接）
- 空页面（只有标题没有内容）

## 5. 自主调研

```
1. 确定主题和知识缺口
2. 第1轮：WebSearch 搜索基础信息
3. 第2轮：搜索最新进展和争议
4. 第3轮：搜索实践案例和最佳实践
5. 综合整理，创建/更新 wiki 页面
6. 标记新增知识和仍存在的缺口
```

### 模式 A：普通笔记

**路径**：`C:\Users\30817\Documents\Obsidian Vault\02-学习\{主题}.md`

**规则**：
- 每条笔记包含时间戳 `YYYY-MM-DD HH:MM`
- 使用 `##` 分隔主题，`###` 分隔子主题
- 使用 `==高亮==` 标记核心概念
- 使用 `> [!NOTE]` / `> [!TIP]` 标记重要信息
- 新内容追加到文件末尾，不覆盖

**模板**：
```markdown
---
created: {{DATE}} {{TIME}}
updated: {{DATE}} {{TIME}}
tags: [{{TAGS}}]
---

# {{主题}}

## {{DATE}} {{TIME}} - {{标题}}

### 概述
{{简要描述}}

### 核心要点
- =={{要点1}}==
- =={{要点2}}==

### 详细内容
{{详细学习内容}}

### 相关链接
- [[相关笔记]]

### 待办
- [ ] {{待办}}
```

## 执行规则

1. **先扫描再行动**：始终先了解笔记库当前状态
2. **保留原有结构**：不破坏用户已有的笔记组织
3. **双向链接**：每次创建页面都要建立 `[[双向链接]]`
4. **带引用回答**：查询结果必须指向具体笔记路径
5. **增量更新**：不重复创建已存在的页面，只更新差异
6. **热缓存维护**：每次交互后更新 hot.md（最近 500 词上下文）
7. **时间追踪**：每条笔记必须包含时间戳，使用 `Asia/Shanghai` 时区
8. **追加而非覆盖**：普通笔记追加到文件末尾，代码笔记创建新章节文件

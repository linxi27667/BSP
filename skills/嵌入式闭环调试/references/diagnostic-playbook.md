# 诊断决策表

## 构建失败

先看最早的 fatal error，不要被后续级联错误带偏。

- 找不到头文件：检查 include path、组件依赖、CMake/uvprojx。
- 未定义符号：检查源文件是否加入构建、C/C++ linkage、库顺序。
- 类型/宏错误：检查 sdkconfig、芯片型号、HAL 版本、条件编译。
- 资源嵌入失败：检查文件路径、二进制嵌入列表、文件大小。

## 烧录失败

- 端口不存在：重新枚举，检查 USB 线、驱动、设备管理器。
- 端口 busy：关闭串口助手、IDE monitor、RTT/GDB 占用。
- 自动下载失败：提示用户按 BOOT/RESET 或降低波特率。
- Keil 下载失败：检查 Debug Adapter、Pack、Flash Algorithm、Target。

## 看门狗/死锁

- 找任务名、触发 CPU、调用栈。
- 检查长循环是否缺少 delay/yield。
- 检查互斥锁、队列、事件组等待。
- 检查高优先级任务是否饿死低优先级喂狗任务。
- 临时加任务水位、运行计数、关键段耗时。

## 内存/栈

- 关注“最大连续块”，不是只看 free heap。
- 图片、摄像头、音频、DMA、LVGL 常消耗连续 PSRAM。
- FreeRTOS 栈溢出可能表现为随机崩溃。
- 临时降低 buffer、减少缓存、延迟初始化可验证根因。

## 协议链路

按层排查：

1. 物理链路：串口/I2C/SPI/CAN/MQTT 是否连通。
2. 帧边界：头、长度、CRC、大小端。
3. 时序：超时、重试、去重、seq。
4. 业务映射：楼层/设备 ID/命令码/GPIO index。
5. 状态刷新：ACK 是否更新模型，UI 是否订阅事件。

## UI/LVGL

- 卡顿：图片解码、刷新面积、动画、任务优先级、锁竞争。
- 缺字：字体子集缺码点，补字体而不是换文案逃避。
- 图片错位：检查源图尺寸、目标控件尺寸、contain/cover 策略。
- 内存冲突：大 PNG 解码后会占用远超压缩文件大小的 RAM。

## 结束前自检

- 是否仍有临时 debug 打印过多影响实时性？
- 是否有未提交/误提交的备份、日志、临时脚本？
- 是否告诉用户烧录命令和端口？
- 是否明确“已实机验证”还是“仅编译验证”？
